# Eurex API Explorer

A web app for the Eurex GraphQL reference-data API, for Eurex traders and clearers: an explorer for queries, plus
views for products, trading hours, strikes, expirations and API changes.

## Views

| View | What it does |
|---|---|
| API Overview | Entry point with example queries per data domain |
| Products | Search by code, name, ISIN or vendor code; follow products (watchlist) |
| Product card | Master data, trading hours with live status, tick rules with a price checker, TES lot sizes per expiration, upcoming expirations and holidays (`.ics`), settlement price history, vendor codes. Printable. |
| Strike Window | Listed strikes per contract date, delta coverage, request for additional strikes |
| Trading Hours | 24 h timeline per product, open / TES / closed / holiday status, timezones, watchlist filter |
| Calendar | Expirations and exchange holidays of followed products by month, `.ics` export |
| API Explorer | Query editor with schema validation and context-aware suggestions, tabs (one running query per tab, drag to reorder, duplicate, context menu), history and saved queries, results with search, filters, column chooser, paging, CSV / Excel / Markdown export |
| Info | Data freshness per dataset (Eurex calendar aware) and the API changelog, filterable by followed products, `.ics` export |

Everything personal (watchlist, tabs, history, saved queries, display settings) is stored in the browser only.

## AI agents

Four ways in, from simplest to most robust. All share one tool registry (`eurex_mcp/tools.py`), so they cannot drift apart.

**1. Instructions only.** Point any assistant that can send HTTP requests at **`ai.md`** (`https://raw.githubusercontent.com/ViktorHD/eurex-api/main/ai.md`; `ai.html` is the same as a page) and give it your API key. It holds endpoint, authentication, datasets, query syntax, answer patterns for common questions, error handling and rules. `llms.txt` is the short index for crawlers; **`llms-full.txt`** is everything in one file (instructions, tool list, GraphQL schema).

Example prompt: *Read https://raw.githubusercontent.com/ViktorHD/eurex-api/main/ai.md and use it to answer my questions with the Eurex API. My API key (header X-DBP-APIKEY): ...*

**2. MCP server** (Claude, ChatGPT, Cursor, Hermes front ends and other MCP clients). The tools apply the rules for you (product filters, paging, Europe/Berlin trading status, tick grid, TES tiers) and return compact results with the `as_of` date. Two ways to connect, no clone needed:

*Local, one command* (needs [uv](https://docs.astral.sh/uv/)):

```bash
claude mcp add eurex -- uvx --from git+https://github.com/ViktorHD/eurex-api eurex-mcp                      # Claude Code
claude mcp add eurex -e EUREX_API_KEY=... -- uvx --from git+https://github.com/ViktorHD/eurex-api eurex-mcp   # with your own key
```

Claude Desktop, Cursor and most other clients take the same thing as JSON:
`{"mcpServers": {"eurex": {"command": "uvx", "args": ["--from", "git+https://github.com/ViktorHD/eurex-api", "eurex-mcp"], "env": {"EUREX_API_KEY": "..."}}}}`

*Remote, just a URL.* The app serves MCP at `/mcp` (streamable HTTP, stateless, tools only). In a client that supports remote servers add `https://YOUR-APP-HOST/mcp`; for Claude Code: `claude mcp add --transport http eurex https://YOUR-APP-HOST/mcp`. Send your own key as header `X-DBP-APIKEY` (or `Authorization: Bearer <key>`). Without a key the shared demo key is used, limited to 20 calls a minute per address (`EUREX_DEMO_CALLS_PER_MINUTE`). The app must be deployed somewhere public for this: GitHub Pages is static and cannot serve it.

From a clone: `pip install -r requirements-mcp.txt && python -m eurex_mcp.server` (stdio) or `--http --port 8000`.

Tools: `search_products`, `get_product`, `get_market_status`, `get_tick_size`, `get_expirations`, `get_holidays`, `list_contracts`, `get_strikes`, `get_tes_thresholds`, `get_settlement_prices`, `get_changes`, `get_schema`, `run_graphql` (escape hatch, refuses unfiltered `Contracts` / `FlexibleContracts` / `SettlementPrices`), `get_api_info`. Without `EUREX_API_KEY` the shared demo key is used.

**3. Your own agent or a no-code tool.**
- `ai/claude_tools.json` (Anthropic `tools`) and `ai/openai_tools.json` (OpenAI function tools) are generated from the registry. Run the tools with `eurex_mcp.tools.call(EurexClient(), name, args)`.
- The app also exposes the tools over REST: `POST /api/v1/tools/<name>` with the caller's own key in `X-DBP-APIKEY` (forwarded, never stored; there is no server-side key), described by `/openapi.json`. Use that URL in OpenAI Actions, Zapier, n8n or Copilot Studio. `ai/openapi.json` is a static copy with a placeholder server URL.

**4. Schema and checks.**
- `schema.graphql` is the schema of the live API as SDL. It is generated by `python scripts/export_schema.py` (needs network and a key); the `refresh AI assets` workflow does this weekly and opens a pull request. Until the first run the file is absent and `llms-full.txt` says so.
- After changing `ai.md`, the tools or the schema run `python scripts/build_ai_assets.py` (CI runs it with `--check`).
- `evals/` holds 38 questions with live-data checks. `python evals/run_evals.py --mode tools` (model with the tools) and `--mode docs` (model with `ai.md` and one raw GraphQL tool) report pass rate, tool calls, errors and tokens, so a change to the docs or tools can be measured. Needs `ANTHROPIC_API_KEY` and `EUREX_API_KEY` (`requirements-evals.txt`); also available as the manual `AI evals` workflow.

The web app itself has no built-in chat and needs no AI keys.

## Run it

```bash
pip install -r requirements.txt
python app.py                      # http://localhost:8080
```

The app is static, so it also works from GitHub Pages; `app.py` only serves the same files. `DATABRICKS_APP_PORT` sets the port (default `8080`).

## Android app

`android/` is an Android app (Kotlin, minSdk 29) that bundles this front end in a WebView, so all views work as in the browser
and data comes from the Eurex API. A Gradle task copies `index.html` and `explorer/` into the APK at build time;
there is no second copy to maintain. Exports (CSV, Excel, `.ics`) are saved to Downloads and Print opens the Android print dialog.
External links open in the browser. Like the web app, it loads three.js, icons and fonts from CDNs, so it needs a network connection.

```bash
cd android && ./gradlew assembleDebug    # needs JDK 17 and the Android SDK; APK in app/build/outputs/apk/debug/
```

The `android` workflow builds the debug APK on every relevant change, uploads it as an artifact and commits it as `android/eurex-explorer.apk`, ready to install (allow "install unknown apps" for your file manager or browser). It is signed with the fixed debug key in `android/debug.keystore`, so updates install over older builds. In Android Studio, open `android/`.

## Test

```bash
npm ci && npm test                          # front end (Jest)
pip install -r requirements-dev.txt && pytest   # server, MCP tools, REST wrapper, evals harness
```

## Layout

- `index.html`, `explorer/`: the front end (plain ES modules, no build step). `app.js` wires the views;
  each view and helper is its own module with tests in `explorer/tests/`.
- `app.py`: serves the front end, the AI instructions, the hosted MCP endpoint (`/mcp`) and the REST tools (`/api/v1/tools`, `/openapi.json`).
- `ai.md`, `ai.html`, `llms.txt`: instructions for AI agents (keep `ai.md` and `ai.html` in sync; a test checks the key facts).
- `eurex_mcp/`: tool registry (`tools.py`), GraphQL client, pure logic ported from the Explorer, MCP server (stdio/HTTP, `pyproject.toml` installs it as `eurex-mcp`), hosted `/mcp` endpoint (`remote.py`), REST blueprint, tool definitions.
- `ai/`, `llms-full.txt`, `schema.graphql`: generated agent assets (`scripts/build_ai_assets.py`, `scripts/export_schema.py`).
- `evals/`: question set and runner.
- `docs/api-data-proposals.md`: proposed new API queries from public Eurex information.
- `notebooks/`: tutorials and recipes for the API.
