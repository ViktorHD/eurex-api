Eurex Reference Data API: instructions for AI agents

Everything an AI assistant needs to answer questions with the Eurex GraphQL reference-data API. Written to be read by a model: plain structure, copy-ready requests, explicit rules.

For users: give your assistant this prompt. It works as is, with the shared demo key.

Read https://raw.githubusercontent.com/ViktorHD/eurex-api/main/ai.md and use it to answer my questions with the Eurex API. Use the demo key from that page.

Hint: the demo key is shared by everyone, so it can hit rate limits at busy times. For regular use get your own free key on the Deutsche Börse developer portal and add it to the prompt: "My API key (header X-DBP-APIKEY): <your key>".

The prompt points at the plain-text copy of this page (ai.md) because some assistants do not read GitHub Pages sites.

No tool that can send HTTP requests? Ask the assistant for a query and run it in the API Explorer.

2. Rules for the agent

  1. Never guess names. Field and type names are case sensitive (ProductInfos, Contracts, ExpirationDate). If unsure, run the introspection query in section 4 and use what it returns.
  2. Filter by Product for Contracts, FlexibleContracts and SettlementPrices. Without it the result is huge and the request may time out or be cut off.
  3. Select only the fields you need. Smaller answers are faster and cheaper to read.
  4. Find the product code first when the user gives a name, ISIN or underlying (section 6, recipe 1). Product codes are short, e.g. FESX (Euro STOXX 50 futures) and OESX (its options).
  5. Several datasets in one request: put several root fields in one query instead of making several calls.
  6. Report the validity date. Every dataset returns a date; mention it when it matters ("as of 2026-10-09").
  7. Do not invent data. If the API returns nothing or an error, say so. Do not fill gaps from memory: contract specifications and trading hours change, and the API is the source of truth.
  8. Cannot send POST requests? Give the user the finished query and tell them to run it in the API Explorer.
  9. Prefer the user's own key over the demo key. Do not store or repeat a user's own key in your answers. If the demo key is rate limited (HTTP 429), tell the user once that it is shared and that a free personal key from the developer portal avoids this.

3. First request

curl -sS -X POST https://api.developer.deutsche-boerse.com/eurex-prod-graphql/ \
  -H 'Content-Type: application/json' \
  -H 'X-DBP-APIKEY: YOUR_KEY'   # or the demo key from section 1 \
  -d '{"query":"{ ProductInfos(filter:{Product:{eq:\"FESX\"}}) { date data { Product Name ProductISIN Currency ContractSize TickSize TickValue } } }"}'

Response shape

Every dataset is a root field that returns an object with the validity date and a list data. When a dataset is paged, pageInfo sits next to them.

{ "data": { "ProductInfos": {
    "date": "2026-10-09",
    "data": [ { "Product": "FESX", "Name": "...", "Currency": "EUR" } ],
    "pageInfo": { "hasNextPage": false, "endCursor": null }   // only if requested
} } }

4. Discover the schema (introspection)

Standard GraphQL introspection works. Start with the list of datasets (root queries) and their arguments:

{ __schema { queryType { fields { name description args { name type { name kind } } type { name kind ofType { name kind } } } } } }

Then the fields of one result type (use the type name from above, and its data field's item type):

{ __type(name: "Contract") { fields { name type { name kind ofType { name } } } } }

The filter input types show the exact operators available per field: { __type(name: "ContractsFilter") { inputFields { name type { name } } } } (the type name may differ; look it up from the filter argument of the root field).

6. Query syntax

Filter

Contracts(filter: { Product: { eq: "FESX" } }) { ... }
TradingHours(filter: { Product: { eq: "FESX" } }) { ... }

eq is the operator used throughout. Do not assume others (in, ne, ranges): read the available operators and the value formats (for example dates) from the filter input type with introspection (section 4) before using them. When in doubt, filter by Product and do the rest of the filtering yourself on the returned rows.

Sort

Holidays(filter: { Product: { eq: "FESX" } }, sort: { field: Holiday, order: ASC }) { ... }

field is an enum value (no quotes), order is ASC or DESC.

Paging

Large results are paged by cursor. Ask for pageInfo and pass the cursor back until hasNextPage is false:

Contracts(filter: { Product: { eq: "OESX" } }, page: { first: 200 }) {
  date
  data { Contract Strike ExpirationDate }
  pageInfo { hasNextPage endCursor }
}
# next page: page: { first: 200, after: "<endCursor>" }

Variables

{"query": "query ($p: String) { Holidays(filter: { Product: { eq: $p } }) { date data { Holiday ExchangeHoliday } } }",
 "variables": { "p": "FESX" }}

Recipes

  1. Find a product by name, ISIN or underlying. Load the product list once (ProductInfos { data { Product Name ProductISIN ProductType Currency } }, no filter, about one row per product), then search it yourself (case-insensitive over Product, Name, ProductISIN). Do not guess codes.
  2. Product card in one request: ProductInfos, TradingHours, TickRules, TESProfiles and Holidays, each with filter: { Product: { eq: "FESX" } }.
  3. Next expirations: Expirations(filter: { Product: { eq: "OESX" } }) for the calendar, Contracts for the listed series.
  4. Option strikes for one expiry: Contracts with the product filter, select ContractDate CallPut Strike OptionsDelta, then group by ContractDate yourself.
  5. Is the market open / what are the hours? TradingHours gives the phase times; Holidays gives days without trading. State which time zone the data uses only if you have verified it from the data or documentation.
  6. What changed recently? Changelog { data { Date Type Description Query } }; the Query field names the affected dataset.

7. Errors and limits

SymptomMeaning and action
HTTP 401 / 403Key missing or invalid. Check the header name and value; if the user's own key fails, ask them to verify it.
HTTP 429Rate limit. Wait for the Retry-After seconds (or about 10 s) and retry once; do not hammer the API.
HTTP 5xx or timeoutTemporary. Retry later or narrow the query (add filters, fewer fields, page: { first: N }).
HTTP 200 with errorsGraphQL error such as an unknown field. Read errors[].message, fix the query, and use introspection instead of guessing. If data is also present, the answer is partial: use what is there and say what is missing.
Empty data listNo match. Check the product code and the filter value; do not conclude that a product does not exist before looking it up in ProductInfos.

8. Answering the user

  • Answer in plain words first; add a small table when the data is a list.
  • Name the product (code and name), the dataset and the validity date you used.
  • Show the GraphQL query only if the user asks for it or wants to rerun it.
  • Say clearly when something is not available in the API instead of estimating it.

9. Answer patterns

Proven ways to answer frequent questions. Dates and times below are Eurex time (Europe/Berlin), the convention of the API Explorer.

QuestionHow
Next expiration of a productExpirations(filter: { Product: { eq: "OESX" } }); keep rows with ExpirationDate today or later, take the earliest. Report date, ExpirationIndex and MasterContract.
Is the product trading now?TradingHours + Holidays for the product. Weekend: closed. Today in Holidays: holiday. Now inside StartContinuousTrading..EndContinuousTrading: open. Else inside StartTES..EndTES: only TES. Else closed. A range that ends before it starts runs over midnight.
Tick size at a priceTickRules for the product. Use TradeType ORDER_BOOK and the simple InstrumentType unless asked otherwise; BLOCK without own rules follows the order book. A band covers StartPrice up to EndPrice (EndPrice excluded when the next band starts there, included otherwise; empty EndPrice is open ended). A price is valid when it is a whole multiple of PriceStep.
Minimum TES lot size for the n-th expiryTESProfiles + Expirations. MinExpiryRange is the expiration index (1 = front expiry) from which a row applies until the next row starts. Use the row with the highest MinExpiryRange not above n.
Strikes of an option for one expiryContracts with the product filter; select ContractDate CallPut Strike OptionsDelta; keep the wanted ContractDate; list unique strikes sorted.
Latest settlement priceSettlementPrices with the product filter; take the newest SettlementDate for the wanted ContractID and PriceType. Narrow the result; the history is large.
Is something changing for a product?Changelog; keep entries whose Description, OldValue, NewValue or Query mention the product or dataset; newest first.

10. Tools instead of raw GraphQL

If your client supports MCP, use the MCP server in this repository (python -m eurex_mcp.server, see the README) instead of writing queries: search_products, get_product, get_market_status, get_tick_size, get_expirations, get_holidays, list_contracts, get_strikes, get_tes_thresholds, get_settlement_prices, get_changes, get_schema, run_graphql. They apply the rules and patterns above. Tool definitions for the Claude and OpenAI APIs are in ai/claude_tools.json and ai/openai_tools.json; an OpenAPI document is in ai/openapi.json. The full schema is in schema.graphql and everything in one file in llms-full.txt (both once generated).
